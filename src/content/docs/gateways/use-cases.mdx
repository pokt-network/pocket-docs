Teams building on Pocket Network's gateway infrastructure fall into four patterns:

## 1. Commercial RPC Provider

Build a managed API service powered by Pocket's decentralized supplier pool, for blockchain RPC or any other service on the network. Set your own pricing, issue API keys, and keep the margin between customer revenue and protocol cost.

**Why Pocket:** Lower infrastructure cost than running your own backends, a growing catalogue of services behind one integration, decentralized redundancy without managing it yourself.

## 2. dApp Infrastructure

Run a gateway dedicated to your own application's traffic. Instead of paying a centralized provider per request, stake POKT and route your traffic through the network directly.

**Why Pocket:** Predictable costs (proportional to usage), no vendor lock-in, censorship resistance for critical infrastructure.

## 3. AI Agent Data Layer

Route AI agent traffic through Pocket — data APIs, LLM inference, blockchain queries, and any other service on the network. The Foundation's [Agentic Portal](/agent-services) is a working example: a gateway-backed front door where agents pay per call over x402 or MPP.

**Why Pocket:** a growing catalogue of services through one interface, no API key management for agent fleets, and per-call payment that agents can make on their own.

## 4. Chain Foundation Partnership

Chain foundations sponsor Pocket endpoints for their developer communities. PNF provides dedicated, unlimited access at wholesale (protocol burn cost only).

**Why Pocket:** Decentralized infrastructure and an existing set of chains already served on the network. Contact [directors@pokt.foundation](mailto:directors@pokt.foundation).
